# 16 — Migrations & Incident Response

The two situations where SEO work is time-critical and mistakes are expensive to reverse.

## Risk by migration type

| Type | Risk | Typical recovery |
|---|---|---|
| HTTP → HTTPS | Low | 1–4 weeks |
| www ↔ bare domain | Low | 1–4 weeks |
| URL structure change (same domain) | **Medium-high** | 4–12 weeks |
| Domain change | **High** | 4–12 weeks |
| Platform / CMS change | **High** | 4–12 weeks |
| Site merge or split | **Very high** | 3–6 months |
| Redesign with URLs unchanged | Low-medium | 2–6 weeks |

- ⚠️ **Change one big thing at a time.** If the domain, the design and the platform all move together, a problem afterwards has no attributable cause.

## Before (T-4 weeks)

- [ ] **Complete URL inventory**, from the union of five sources: a full crawl, the sitemaps, GSC (all pages over 16 months), analytics (12 months of landing pages), server logs (3 months of crawled URLs), and the URLs your backlink tool says are linked. Any one source alone will miss pages.
- [ ] **Baseline**: organic traffic, impressions, average position, indexed page count, CWV, and the rankings of the top 100 URLs. You cannot prove a migration went well without the number it started at.
- [ ] **1:1 redirect map** as a CSV, generated by rule plus an explicit exceptions list.
- [ ] Crawl the new site on staging — missing pages, broken links, missing metadata.
- [ ] Staging is behind `noindex` **and** auth.
- [ ] New sitemaps ready; new GSC property verified; DNS TTL lowered.
- [ ] **Rollback plan written down**, with its trigger thresholds agreed in advance.

## Day 0

1. Ship, activate redirects.
2. **Test the entire redirect map** — not a sample:
   ```bash
   while IFS=, read -r old new; do
     result=$(curl -s -o /dev/null -w '%{http_code} %{redirect_url}' -m 10 "$old")
     echo "$old → $result (expected: 301 $new)"
   done < redirect-map.csv
   ```
3. Verify robots.txt (a leftover `Disallow: /` is the classic disaster).
4. Scan production for `noindex`.
5. Submit the new sitemap — and **leave the old one in place for a while** so Google recrawls the old URLs and sees the redirects.
6. Domain change: use GSC's **Change of Address** tool.
7. Repoint analytics, monitoring and CDN configuration.

**First 72 hours:** watch 5xx, 404 spikes, CWV regressions, traffic anomalies.
**First 4 weeks:** watch old URLs move to "Page with redirect" in the Pages report, and the new URLs' indexing curve.

**Expected behaviour:** 2–6 weeks of fluctuation is normal. Still 20%+ down after 8 weeks means the migration is wrong — re-audit the inventory and the redirect map rather than waiting longer.

## Redirect rules

- ✅ **301** for permanent moves. A 302 delays signal transfer.
- ✅ **No chains.** `A→C` and `B→C`, not `A→B→C`.
- ✅ **1:1.** Bulk-redirecting everything to the homepage is treated as a soft 404 and loses the lot.
- ✅ No equivalent page? Redirect to the nearest relevant category, or return **410**.
- ✅ Keep redirects for **at least a year**, ideally forever.
- ✅ Update internal links, canonicals, hreflang and sitemaps to the **new** URLs. Continuing to link to a redirect wastes crawl budget and dilutes the signal.

## Hack and security incidents

Symptoms: unknown pages in the index, a cloaking warning, ranking for pharmaceutical keywords, a GSC security notification.

1. Take the site offline or isolate the source — stop the spread first.
2. Inspect logs and the filesystem; find the entry point.
3. Restore from a clean backup and **close the hole** (dependency, credential, permission).
4. Remove injected pages with **410**; clean any spam sitemap.
5. Rotate every session and API key.
6. Request a security review in GSC.
7. Afterwards: 2FA, dependency scanning, WAF, file integrity monitoring.

## Rollback criteria

Decide these before you need them, so nobody is negotiating during an incident:

- 5xx rate above 5% for more than 30 minutes → **roll back**
- Organic traffic down more than 40% in 48 hours with no technical cause found → **roll back**
- A critical conversion flow broken → **roll back**
- Partial indexing fluctuation → **wait.** A second migration does more damage than the first.

## Checklist
- [ ] URL inventory merged from all five sources
- [ ] Baseline metrics recorded
- [ ] 1:1 redirect map tested end to end, no chains
- [ ] robots.txt and `noindex` verified in production
- [ ] Old and new sitemaps both submitted
- [ ] Change of Address tool used (domain moves)
- [ ] Internal links updated to the new URLs
- [ ] Monitoring and rollback thresholds written down
- [ ] Weekly comparison report for 8 weeks
